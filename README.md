# 🦃 مزرعه بوقلمون — نسخه React

سامانه جامع مدیریت مزرعه پرورش بوقلمون — بازنویسی‌شده با **React 19 + TypeScript + Vite**.

> نسخه اول (Vanilla JS) در پوشه [`legacy/`](./legacy) نگهداری می‌شود.

## ✨ امکانات

| بخش | توضیح |
|---|---|
| **داشبورد** | موجودی زنده گله، شاخص‌های کلیدی، نمودار هزینه/درآمد، ترکیب هزینه‌ها، هشدارها و تراکنش‌های اخیر |
| **گله‌ها** | کارت هر دوره پرورش با موجودی، تلفات، وزن و پیشرفت دوره؛ صفحه جزئیات با ۴ تب |
| **ثبت روزانه** | تلفات، حذفی، دان، آب، دما و وزن نمونه — با محاسبه خودکار سن گله |
| **هزینه‌ها** | ۱۹ دسته با زیردسته، جستجوی زنده، فیلتر تاریخ و گله، خروجی CSV، نمودار دونات |
| **فروش** | ثبت فروش بر اساس نوع محصول، محاسبه خودکار مبلغ، جدول تجمیعی و نمودار |
| **شرکا** | درصد سهام، آورده/برداشت، تقسیم هزینه‌ها بین شرکا، جدول تسویه و **پیشنهاد حداقل انتقالات** |
| **خوراک** | فرمول ساختگی با درصد مواد، قیمت و پروتئین؛ محاسبه زنده هزینه هر کیلو و بچ‌های تولید |
| **انبار** | موجودی، حد هشدار، ارزش انبار، ورود/خروج با ثبت خودکار هزینه |
| **کارها** | تفکیک عقب‌افتاده / امروز / پیش‌رو / انجام‌شده با یادآور |
| **گزارش‌ها** | صورت سود و زیان، مقایسه ماهانه، تفکیک دسته‌ها، تقسیم سود شرکا، مقایسه گله‌ها |
| **تنظیمات** | اطلاعات مزرعه، ارقام فارسی، پشتیبان‌گیری/بازیابی JSON و بازنشانی |

### مدیریت وضعیت

بدون Redux یا کتابخانه اضافه:

- استور ماژولار با `useSyncExternalStore` — هر تغییر یک snapshot تازه می‌سازد
- وضعیت **تغییرناپذیر** است؛ همه کامپوننت‌ها با `useApp()` دوباره رندر می‌شوند
- ذخیره خودکار در `localStorage` (کلید `turkeyFarm.v3`) با مهاجرت خودکار از نسخه قبلی (`turkeyFarm.v2`)
- سلکتورها توابع خالص‌اند: `flockStats`، `totals`، `settlement`، `byCategory`، `alerts`، `suggestTransfers`

## ☁️ اتصال به Supabase

داده‌ها در Supabase ذخیره می‌شوند (نه localStorage) و با احراز هویت از هم جدا می‌شوند.

**۱. اجرای اسکیمای دیتابیس**

فایل [`supabase/schema.sql`](./supabase/schema.sql) را در **Supabase → SQL Editor** اجرا کنید.
این فایل دو جدول می‌سازد:

| جدول | نقش |
|---|---|
| `tf_records` | همه رکوردها (`kind` = نوع مجموعه، `data` = بدنه JSON) |
| `tf_settings` | تنظیمات مزرعه (یک ردیف برای هر کاربر) |

**۲. امنیت**

- RLS روی هر دو جدول فعال است؛ هر کاربر فقط `user_id = auth.uid()` خودش را می‌بیند
- کلید `anon` عمومی است و به‌تنهایی هیچ دسترسی‌ای نمی‌دهد — محافظ واقعی RLS است
- بدون ورود، هیچ داده‌ای قابل خواندن یا نوشتن نیست

**۳. ساخت حساب مدیر (بدون ثبت‌نام عمومی)**

این سامانه **یک مدیر** دارد و ثبت‌نام در آن وجود ندارد. حساب مدیر را یک‌بار خودتان بسازید:

1. Supabase → **Authentication → Users → Add user**
2. ایمیل و رمز بگذارید و تیک **Auto Confirm User** را بزنید
3. در صفحه ورود برنامه با همان ایمیل/رمز وارد شوید

برای قفل کامل، فایل [`supabase/single-admin.sql`](./supabase/single-admin.sql) را هم اجرا کنید:
اولین کاربر به‌عنوان مدیر ثبت می‌شود و از آن به بعد ساخت هر کاربر جدید — حتی از داشبورد Supabase — با خطا رد می‌شود.

**۴. متغیرهای محیطی (اختیاری)**

پروژه با مقدار پیش‌فرض داخل `src/lib/supabase.ts` کار می‌کند. برای پروژه دیگر، فایل `.env` بسازید:

```bash
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGci...
```

**همگام‌سازی چطور کار می‌کند؟**
هر تغییر اول در حافظه اعمال می‌شود (UI فوری)، بعد به‌صورت تفاضلی به Supabase می‌رود —
فقط رکوردهای تغییرکرده `upsert` و حذف‌شده‌ها `delete` می‌شوند. نشانگر «همگام / در حال ذخیره…» در نوار بالا وضعیت را نشان می‌دهد.

**ویوهای اختیاری:** فایل [`supabase/views.sql`](./supabase/views.sql) چند ویو خوانا (`tf_v_expenses`، `tf_v_sales`، `tf_v_flocks`، `tf_v_partners`) می‌سازد تا داده‌ها را در Table Editor مثل جدول معمولی ببینید.
